# Гант Великий

Универсальная десктоп-программа «Диаграмма Ганта» для управления проектами (Windows, один .exe) с двусторонним обменом с 1С «Управление IT-отделом 8».

- Исходное ТЗ: [docs/ТЗ.md](docs/ТЗ.md) (версия от 24.09.2026). Раздел «Изменения требований» ниже важнее ТЗ.
- Макет интерфейса (17 экранов): https://claude.ai/artifact/G7TJtBj8PA5TadWcgKUFWU
- Руководство пользователя: [docs/guide.md](docs/guide.md) (оно же в программе, Ctrl+F1); что нового по версиям — [docs/changes.md](docs/changes.md).
- Документы Этапа 0 (в `docs/`): [план этапов](docs/plan.md), [формат обмена](docs/format.md) + [схема](schema/gantt-exchange.schema.json) + [примеры](examples/), [источники и форматы файлов](docs/import-export.md), [HTTP-контракт](docs/api.md), [архитектура](docs/architecture.md), [интерфейс](docs/ui.md), [вопросы и риски](docs/questions.md).

## Как работаем

- Этапы 0–5 из ТЗ. Код приложения — только после согласования Этапа 0. После каждого этапа — остановиться, показать результат, дождаться подтверждения.
- Каждый этап ведём в своей ветке (`stage-0`, `stage-1`, …); после согласования этапа — слияние в `main`.
- Репозиторий https://github.com/imkita339-afk/-Gantt-the-Great открытый. `main` на GitHub начинается с чистого коммита «Гант 1.0» (26.09.2026). История до него — только локально, в ветках `archive-main`, `stage-0`, `stage-1`: в ней выдуманные фамилии, наружу её не отправляем. Новые этапы — ветки от нового `main`.
- Новая версия: номер в `gantt/__init__.py`, раздел в `docs/changes.md`, `tools/build_exe.py`, тег `v<версия>`, `tools/publish_github.py imkita339-afk/-Gantt-the-Great`.
- Не хватает данных или есть развилка — спросить, а не угадывать. Про метаданные 1С — только то, что есть в выгрузке конфигурации.
- Все принятые решения — в этот файл. Коммит после каждого логического шага.
- Язык интерфейса, документации и общения — русский.

## 1С: ограничения

- Разработка и проверка — только на копии IT-базы; в рабочую базу ничего не пишем без отдельного разрешения.
- Основную конфигурацию не меняем — только расширение. Не пишем напрямую в СУБД, не подключаем внешние компоненты без согласования.
- В 1С ничего не отправляется без явного нажатия «Подтвердить».

## Реальные данные — только в `local/`

Excel-выгрузки, выгрузка конфигурации 1С (код вендора) и всё с ФИО сотрудников лежат в `local/` (в `.gitignore`). В репозиторий — только выдуманные демо-данные (`tools/make_demo.py`); ничего из присланных файлов, даже в обезличенном виде.

## Решения

### Эталонный Excel

- Пример отчёта 1С ProjectsToGanttExport, присланный пользователем, лежит только в `local/`; его разбор — `local/excel-analysis.md`, ожидаемые числа для теста — `local/expected.json`. Из него в репозиторий не попадает ничего: ни данные, ни обезличенные производные (названия, номера, даты, числа).
- Колонки отчёта искать по заголовкам, а не по позиции: состав колонок меняется между версиями отчёта.

### Источники данных и форматы файлов

- Ядро программы работает только с форматом обмена gantt-exchange. Каждый внешний формат — отдельный адаптер (чтение и/или запись); новый формат добавляется новым адаптером без изменения ядра.
- Открыть можно: файл обмена (JSON), Excel, CSV, вставку таблицы из буфера обмена, MS Project XML, а также данные с сервера по HTTP-контракту (1С или любая система).
- Для таблиц (Excel, CSV, буфер) — мастер сопоставления колонок с сохранением шаблона; отчёт 1С ProjectsToGanttExport распознаётся встроенным шаблоном.
- Сохранить можно в формат, который пользователь выберет при сохранении: файл обмена (JSON), Excel, CSV, MS Project XML; для показа — PDF/PNG диаграммы. Полностью без потерь — только файл обмена; при сохранении в другой формат программа говорит, что не сохранится.
- Всё, что программа сохраняет в Excel/CSV/MS Project, она же умеет открыть обратно.

### Статус и процент задания

- В 1С (IT-база) статус и процент есть — через HTTP-сервис и выгрузку расширения они приходят настоящими. Где именно хранятся — определить по выгрузке конфигурации.
- Табличный источник (Excel/CSV): если в таблице есть колонки статуса и процента — берём их. Если нет (как в отчёте ProjectsToGanttExport) — вычисляем:
  - есть «Дата выполнения» → «Выполнено», полоса от «Даты» до «Даты выполнения»;
  - нет «Даты выполнения», есть срок и он прошёл → «Просрочено» (вычисляемый признак программы для любого источника; в файл обмена пишется «В работе»);
  - нет «Даты выполнения», есть срок и он не прошёл → «В работе», план окончания = срок;
  - нет ни «Даты выполнения», ни срока → «В работе»: задача не закончена, полоса от «Даты» до сегодня с открытым концом;
  - процент проекта = выполненные задания / все задания (как «3/5»).

### Программа (с шага 1.1)

- Python 3.14 + PySide6 6.11 в `.venv`; запуск — `run.bat`, тесты — `.venv\Scripts\python -m pytest`. Код — пакет `gantt/`.
- Окно: слева дерево-таблица, справа шкала — два `QTreeView` на одной модели (строки совпадают всегда), общая прокрутка, раскрытие и выделение.
- Набор данных отчёта 1С — `excel:ProjectsToGanttExport|ProjectsToGanttExport`, а не имя файла: правки переживают новые выгрузки.
- Правки — слой поверх данных источника: `%LOCALAPPDATA%\Гант\data.sqlite`; настройки вида — `settings.ini` там же. Отмена/повтор — `QUndoStack`.
- Цвет проекта — поле `color` узла в формате обмена; правка цвета — оформление: в снимок файла обмена она попадает (в `changes`), а в источник (сервер, выгрузка правок) — нет.
- Проекты — пастельные палитры (Пастель, Тёплая, Холодная, Приглушённая), прогресс — тоном темнее; задания — по статусу или цветом своего проекта (настройка).
- «Проект» — уровень над самым нижним по `levels.order`; у плоского списка проектов нет.
- Сборка: `tools/build_exe.py` → `dist/Gantt.exe` (PyInstaller, один файл, иконка `gantt/resources/gantt.ico` из `tools/make_icon.py`, сведения о версии). Пробная сборка 25.09.2026: 49 МБ, `--version` ≈ 1,2 с, окно с демо-данными ≈ 1,6 с.
- Оконный .exe: к консоли подключаемся только для `--help`/`--version`; служебная переменная `GANTT_SCREENSHOT=путь.png` — снимок окна и выход (проверка сборки без экрана), `GANTT_DATA_DIR` — своя папка данных.

### Форматы, правки и сервер (пачки C и D)

- Снимок в файл обмена: в `nodes` — значения источника, все правки — в `changes`. Открытие снимка берёт в очередь правки, которых ещё нет. Раньше значения «запекались» в узлы, и открытие снимка стирало правки исходного набора — исправлено.
- Excel, CSV и MS Project получают видимые значения (правки внутри). Сохранённая «Гант-таблица» — отдельный набор данных (`table:Гант-таблица|имя файла`), правки исходного отчёта не трогает.
- Незнакомая таблица → мастер; шаблон узнаётся по заголовкам (и по листу Excel). Перечитывание файла без шаблона использует сопоставление, выбранное в мастере в этом сеансе.
- `changeId` правки — UUIDv5 от набора, узла, поля и значения: повторная отправка той же правки — тот же id, сервер отвечает прежним результатом.
- Сервер: `urllib` в фоне (`QThreadPool`), пароль — только в диспетчере учётных данных Windows (или до закрытия программы, если «сохранить» снято). Без связи — сохранённая копия (`%LOCALAPPDATA%\Гант\cache`), повтор 15 с → ×2 → до 10 мин.
- В источник ничего не уходит без окна «Подтвердить». Ответ: записанное становится значением источника и уходит из очереди; конфликт и отказ — выбор, по умолчанию «взять из источника».
- `editable` из источника соблюдается: запрещённые поля не редактируются ни в окне, ни перетаскиванием, ни из пакета правок.
- Тестовый сервер — `gantt/mock_server.py` на `http.server` (FastAPI не нужен), встроен в программу, слушает только `127.0.0.1`.
- PDF/PNG рисуются тем же делегатом полос, что экран, на светлой теме; PDF — весь период по ширине листа, строки по листам.

### Плавность и наглядность (26.09.2026)

- План — светлая дорожка с рамкой, факт — насыщенная полоса того же цвета внутри неё. «Идёт» — факт до сегодня со стрелкой; нет срока — дорожка растворяется; срок прошёл — красная штриховка до сегодня и «+N дн.»; закончили позже — красный хвост факта и риска срока. Прогресс проекта — подписью и в колонке, не заливкой полосы (чтобы не путать с фактом).
- Обозначения: строка под диаграммой (отключается) и полная легенда (F1, «Все обозначения…»). Колонка «Срок» (новая, видна и у тех, у кого настройки уже сохранены); красный счётчик просрочек у проектов и разделов; «Сегодня, дд мес» в шапке; зебра.
- Скорость: строки таблицы и шкалы рисуются своим `drawRow`; сетка шкалы — одна полоска-картинка на кадр; наведение обновляет только две строки; вертикальная прокрутка всегда сдвигает картинку (у Qt в попиксельном режиме иначе бывает полная перерисовка); фильтр — предрасчёт видимых id и `invalidate()` одной сменой раскладки. Замер на отчёте из `local/` (1053 строки): кадр прокрутки ≈ 5–12 мс, масштаба ≈ 10 мс, наведения ≈ 2 мс, поиск 150 мс (было 40–75 мс на кадр и 0,76 с на поиск).
- Фильтры и полная легенда — `Popover`: дочерний виджет окна (не отдельное окно), закрывается щелчком мимо или Esc; диалоги и выпадающие списки внутри работают.
- Карточка при наведении — отдельное окно-подсказка без фокуса: 0,42 с на шкале и 0,65 с в таблице, плавно появляется и «скользит» за курсором; стандартные подсказки строк отключены.
- Разрыв между таблицей и шкалой: ширина таблицы ограничена колонками, лишнее место схлопывается (переход и лёгкий отскок, затем пульс).

### Группы колонок (26.09.2026)

- Ctrl+щелчок по заголовку отмечает колонку (подсветка); когда Ctrl отпущен, отмеченные встают рядом (в порядке показа, с места первой) и становятся группой. Колонка — только в одной группе; «Наименование» не группируется.
- Над заголовком появляется полоска групп (16 пикс. внутри той же высоты шапки — строки таблицы и шкалы по-прежнему совпадают): скобка и «−» у развёрнутой группы, «+» на месте свёрнутой. Меню заголовка: свернуть/развернуть, разгруппировать.
- Свёрнутая группа прячет колонки, не трогая выбор колонок в меню; группы хранятся в настройках вида (`column_groups`).
- Колонка появилась — таблица расширяется на её ширину (но шкале остаётся ≥ 320 пикс.) с отскоком; исчезла — схлопывается. Во время отскока ограничение ширины таблицы снято, чтобы не мелькал разрыв.
- В меню флажки видны в любой теме: пустой квадрат — выключено, акцентный с белой галочкой (`gantt/resources/check.png`, рисует `tools/make_icon.py`) — включено.
- Меню заголовка — «Порядок как в источнике» и список колонок `ColumnList` (`gantt/ui/columns.py`, один виджет в `QWidgetAction`): строки в порядке показа, щелчок — показать/скрыть без закрытия меню; справа у колонок группы — скобка с «−»/«+» и «×»; «Сгруппировать…» или Ctrl+щелчок по строке — режим отметки, «Сгруппировать (N)» собирает группу. Скрытую колонку в группу не берём.
- В «Настройках» «Колонки таблицы» — тот же `ColumnList` (плотнее, `compact`), отдельной правой колонкой; «Работа с файлами» — под «Оформлением». Список меняет настройки окна сразу, поэтому `SettingsPanel._collect` собирает поля поверх `win.settings`, а не своей копии — иначе правка другой настройки откатывала бы колонки и группы.
- Колонки, выключенные в меню, в группе над заголовком не учитываются: все выключены — ни скобки, ни «+», полоски групп нет; в настройках группа остаётся. Включение колонки из свёрнутой группы разворачивает группу. В `header.groups` у группы есть `index` — номер в `column_groups`.

### Шрифт и размеры панелей (26.09.2026)

- Тема и шрифт применяются в начале `MainWindow.__init__`, до создания виджетов: иначе сохранённый размер шрифта при запуске до них не доходил. Стиль всей программы (`apply_theme`) пересобирается только при смене темы, акцента или шрифта — переключение колонки ≈ 27 мс вместо ≈ 95.
- `Popover.open` сбрасывает все вложенные раскладки: шрифт мог смениться, пока панель была скрыта, и подписи плиток темы обрезались.
- Строка обозначений — на раскладке, высота по шрифту: «Все обозначения…» без многоточия при любом шрифте.
- «Все обозначения»: каждое обозначение — блок (образец, название, приглушённое описание), между блоками черта; заголовки разделов — `<big>`.

### Панели и уровни (26.09.2026)

- «Фильтры», «Изменения», «Тема», «Настройки», «Все обозначения» — одинаковые всплывающие панели под своей кнопкой (`Popover`); открыта одна за раз. Док «Изменения» убран, «Настройки» — панель в три колонки (если окно узкое — прежнее отдельное окно), «Тема» — плитки тем, акцентов и палитр.
- В панелях нет общей прокрутки: ширина — по содержимому, фильтры в две колонки; списки не выше своих строк (до 6–10), длинные названия — с многоточием и полным текстом в подсказке; прокручивается по вертикали только список.
- Флажки везде видимые (квадрат акцентного цвета с галочкой) — и в меню, и в списках, и в окнах.
- Кнопки «1 2 3…» слева в заголовке «Наименование» (как в Excel): показать дерево до уровня; число кнопок — по глубине данных, подсказки — по названиям уровней. Кнопка «Уровни» с панели инструментов убрана (пункты остались в меню «Вид»).

### Установка и обновления (26.09.2026)

- Установщик — та же программа: `GanttSetup-<версия>.exe` — копия `Gantt.exe`, узнаёт себя по имени файла (или `--install`). Inno Setup/NSIS не нужны, а окно установки — в стиле и на языке программы.
- Ставится для одного пользователя без прав администратора: `%LOCALAPPDATA%\Programs\Гант\Gantt.exe`, ярлыки (`QFile.link`), запись в `HKCU\...\Uninstall\Gantt`. Удаление — `Gantt.exe --uninstall`; папку с запущенным .exe удаляет скрытый PowerShell после выхода (только `CREATE_NO_WINDOW`: с `DETACHED_PROCESS` PowerShell молча ничего не делает).
- Перед заменой файлов открытую программу просят закрыться через канал одного экземпляра (команда `quit`).
- Источник обновлений — папка (в том числе сетевая) или адрес с `latest.json`: версия, файл, размер, SHA-256, что нового. Установщик, лежащий рядом с `latest.json`, запоминает эту папку. `tools/build_exe.py` готовит `dist/update` — её содержимое копируется в источник.
- Замена себя: запущенный `Gantt.exe` переименовывается в `Gantt.old*.exe` (Windows это разрешает), на его место кладётся новый, запуск с `--updated <старая версия>`. Новая версия ждёт, пока закроется старая, затем удаляет `Gantt.old*.exe` и скачанные установщики и сверяет версию в «Приложениях». Проверено вживую: установка → `--update` → перезапуск → удаление.
- Настройки обновлений — в `settings.ini` (`update/source`, `update/auto`, `update/skip`), а не в настройках вида: «Сбросить к стандартным» их не трогает.
- Ключи администратора: `--install`/`--uninstall` с `--silent`, `--dir`, `--no-desktop`, `--no-start-menu`, `--update-source`, `--remove-data`; `--update` — обновить без окон (0 — обновлено, 3 — уже последняя, 1 — ошибка).
- Тесты не трогают настоящий реестр и рабочий стол: `GANTT_REG_KEY`, `GANTT_SHORTCUTS_DIR`.
- Обновления с GitHub (26.09.2026, по вопросу пользователя): источник `github:владелец/репозиторий` или ссылка на репозиторий → `https://github.com/<репо>/releases/latest/download/latest.json` (постоянная ссылка на последний выпуск, не API — без лимита 60 запросов в час; urllib сам идёт по переадресациям и берёт прокси Windows). В `latest.json` выпуска — полная ссылка на установщик этого тега (`v<версия>`), а не «последний». Выкладывает `tools/publish_github.py` (токен только из `GITHUB_TOKEN`, сначала установщик, потом `latest.json`) или `--prepare` для загрузки на сайте. Репозиторий должен быть открытым; токен в программу не встраиваем. Источник по умолчанию — `UPDATE_SOURCE` в `gantt/__init__.py`: `github:imkita339-afk/-Gantt-the-Great`; свой источник пользователя важнее. В тестах и генераторе картинок автопроверка выключена (`update/auto`), чтобы не ходить в сеть.
- Версия — в `gantt/__init__.py` (1.0.0), людям показываем «1.0» (`short_version`). «Что нового» — `docs/changes.md`; раздел версии уходит в `latest.json`.

### Руководство (26.09.2026)

- `docs/guide.md` — руководство для людей; вшито в .exe. Окно справки — Ctrl+F1 (F1 по-прежнему «Все обозначения»): оглавление по заголовкам, поиск, картинки по ширине текста, «Сохранить в PDF» (свой документ с явными картинками, лист в точках экрана — у копии экранного документа картинки пропадают).
- Картинки — `tools/make_guide_images.py` на выдуманных демо-данных, на настоящем экране (без экрана Qt рисует текст квадратиками). В снимках нет путей с именем пользователя.

### Перетаскивание и режим картошки (26.09.2026)

- Зажатое колесо — `DragPan` (`gantt/ui/smooth.py`), фильтр событий на области шкалы и таблицы: картинка едет за курсором 1:1; отпустили на ходу — инерция (скорость падает в e раз за 325 мс), остановка у края, по нажатию или колесу. Во время перетаскивания карточка скрыта.
- Режим картошки — `potato` в настройках вида; `settings.smooth` = анимации включены и не картошка. Нет анимаций, теней (панели, карточка), скруглений, градиентов, сглаживания полос и таблицы. Замер на отчёте из `local/` (1053 строки): кадр шкалы 9,5 → 5,5 мс, таблицы 8,0 → 6,4 мс; щелчок колеса — 1 кадр вместо ~13, смена масштаба — 1 вместо ~20.
- Значок-картошка в строке состояния (щелчок — выключить) и «Вид → Режим картошки». Флажок «Плавные анимации» в режиме картошки недоступен, но своё значение помнит.

### Шкала: шапка и «изм.» (26.09.2026)

- Шапка шкалы после горизонтального сдвига перерисовывается целиком: подпись месяца у левого края «липкая», и сдвиг готовой картинки оставлял её копии.
- Метка «изм.» акцентного цвета (как в макете) — справа от полосы изменённой строки, вместо точки слева. Если правили сроки — пунктирная рамка плана из источника. В таблице — прежняя точка у названия.
- Подписи у полос обрезаются один раз (кэш); пустое название не рисует пустую подложку.
