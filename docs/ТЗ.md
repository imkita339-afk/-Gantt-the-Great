## Контекст

Я работаю в IT-поддержке. Проекты и задачи отдела ведутся в IT-базе 1С:
- конфигурация «Управление IT-отделом 8», редакция 3.1 (3.1.22.13), softonit.ru;
- расширения: «Расширение ЯСА», «Подсистема телефонии 4.2»;
- платформа 1С:Предприятие 8.3.24.1808.

Руководитель попросил сделать интерактивное, интуитивно понятное мини-приложение для управления проектами в виде диаграммы Ганта с двусторонней интеграцией с 1С.

Сейчас из 1С отчётом формируется Excel-файл с диаграммой Ганта (пример лежит только локально, в репозиторий не входит). **Excel в программе не используется** — ни для импорта, ни для экспорта. Этот файл нужен только как: (1) образец того, как примерно должен выглядеть результат (понедельная шкала, иерархия, цвета статусов); (2) источник реальных тестовых данных — его нужно один раз сконвертировать скриптом в файл обмена (см. ниже).

## Главная идея: один формат обмена

Все данные ходят в **одном формате — «файл обмена Ганта»** (JSON, с версией схемы):
- через **HTTP-сервис 1С** — это тело ответа и запроса;
- через **файл** — тот же самый документ, сохранённый на диск (импорт в программу, экспорт из программы, выгрузка/загрузка в 1С без сети).

То есть HTTP-сервис и файл — два транспорта одного и того же документа. Код разбора, проверки и формирования документа общий и в программе, и в расширении 1С.

Почему JSON, а не XML: в 1С 8.3 есть штатные `ЗаписьJSON`/`ПрочитатьJSON`, в Python — стандартный `json`, для HTTP-сервиса это естественный формат, файлы читаются глазами. XML не делаем, если на Этапе 0 не найдёшь весомой причины (тогда предложи с обоснованием).

**Универсальность:** программа не завязана на мою компанию и на 1С. Любая система, которая умеет отдать документ по схеме (файлом или по тому же HTTP-контракту), подключается без изменения кода. Всё специфичное (набор статусов, уровни иерархии, приоритеты, цвета) приходит в самом документе в разделе справочников; в программе можно только переопределить отображение (цвета, видимость) и запомнить это.

## Что нужно получить

Десктоп-программа для Windows (один .exe, без установки Python у пользователей), работает внутри локальной сети, без авторизации.

## Формат обмена (черновик — доработай на Этапе 0)

Оформи как JSON Schema (`schema/gantt-exchange.schema.json`) и описание с примерами (`docs/format.md`). Черновая структура:

```json
{
  "format": "gantt-exchange",
  "schemaVersion": "1.0",
  "meta": {
    "source": "1C:УправлениеITОтделом",
    "sourceName": "[имя базы]",
    "exportedAt": "2026-09-24T10:04:00+03:00",
    "exportedBy": "[пользователь]",
    "kind": "full | incremental | changes | results",
    "changedSince": null,
    "cursor": "[метка для следующего инкрементального запроса]"
  },
  "dictionaries": {
    "levels":     [{"id": "section", "name": "Раздел", "order": 1}],
    "statuses":   [{"id": "...", "name": "В работе", "kind": "inProgress", "color": "#2F5FD0"}],
    "priorities": [{"id": "...", "name": "Высокий", "order": 3}],
    "urgencies":  [],
    "impacts":    [],
    "people":     [{"id": "...", "name": "Аналитик 1"}]
  },
  "nodes": [{
    "id": "[GUID]", "parentId": "[GUID или null]", "level": "task", "number": "",
    "name": "", "executors": ["[id]"], "initiator": "[id]",
    "planStart": "2026-07-28", "planEnd": "2026-09-23",
    "factStart": null, "factEnd": null, "percent": 70,
    "status": "[id]", "priority": "[id]", "urgency": "[id]", "impact": "[id]",
    "category": "", "custom": {}, "version": "[ВерсияДанных]",
    "editable": ["planStart", "planEnd", "factStart", "factEnd", "status", "percent"]
  }],
  "deleted": ["[GUID]"],
  "changes": [{
    "changeId": "[uuid]", "nodeId": "[GUID]", "field": "planEnd",
    "oldValue": "2026-09-23", "newValue": "2026-10-07", "baseVersion": "[версия]",
    "author": "[ФИО]", "machine": "[имя ПК]", "at": "...", "comment": ""
  }],
  "results": [{"changeId": "...", "result": "applied | conflict | rejected",
               "currentValue": null, "currentVersion": null, "reason": ""}]
}
```

Правила:
- Узлы плоским списком с `parentId` (удобно для инкрементов), уровни и их названия — из `dictionaries.levels`. Число уровней любое.
- `kind` определяет, какие разделы заполнены: `full` — справочники + все узлы; `incremental` — изменённые узлы + `deleted`; `changes` — только `changes` (то, что отправляем в 1С); `results` — ответ 1С по каждому изменению.
- Даты — ISO 8601, `null` для пустых. Кодировка UTF-8.
- `kind` для статуса (`done`, `inProgress`, `overdue`, `release`, `notStarted`) нужен программе для логики и цветов по умолчанию; названия статусов — любые.
- `editable` — какие поля источник разрешает менять (у 1С это белый список).
- Проверка по схеме при каждом импорте; при ошибке — понятный отчёт (какой узел, какое поле), ничего не ломая в текущих данных.
- Подготовь примеры в `examples/`: полный файл из моего Excel, инкремент, пакет изменений, результаты (все исходы).

### Конвертер тестовых данных
Скрипт `tools/xlsx_to_gantt.py` (не часть программы): переводит мою Excel-выгрузку в файл обмена, чтобы было на чём разрабатывать до готовности расширения 1С. Структура Excel:
- лист «Ганта»; строки 1–4 — шапка; колонки A–G: `№`, `Наименование`, `Исполнители`, `Нач. план`, `Оконч. план`, `%`, `Статус`; с колонки H — понедельная шкала (не парсить, полосы строятся по датам);
- иерархия: Раздел → (Группа проектов) → Проект → (Подпроект) → Задача; у раздела текст в A («1.Название раздела»), у проекта число в A, у задачи пустая A и заполненная B; уровни также видны по заливке, образцы — в блоке «Обозначения» внизу (в данные не попадает);
- числа разделов, проектов и задач должны сойтись с исходником;
- даты в форматах `дд.мм.гггг` и `дд.мм.гг`, пустая дата — `—`; исполнители через запятую; статусы `✔ Выполнено`, `✔ Завершён`, `▶ В работе`, `▶ 60% (3/5)`, `⚠ Просрочено`/`⚠ Просрочен`; есть обрезанные «...» названия и дубли;
- GUID в тестовом файле — сгенерированные, но стабильные (одинаковые при повторной конвертации);
- инициатора, приоритета, срочности, влияния и фактических дат в Excel нет — оставь пустыми; в справочники приоритета/срочности/влияния положи значения из 1С («Очень низкий», «Низкий», «Средний», «Высокий»…).

## Запуск из командной строки

```
Gantt.exe "C:\путь\к\файлу.json"
Gantt.exe --import "C:\путь\к\файлу.json"
Gantt.exe --help | --version
```
- Путь позиционным аргументом и через `--import` — одно и то же (позиционный нужен, чтобы работали «Открыть с помощью» и перетаскивание файла на .exe).
- Поддержать пути с пробелами, кириллицей и сетевые (`\\сервер\папка\файл.json`).
- **Один экземпляр:** если программа уже открыта, новый запуск передаёт путь в открытое окно (QLocalServer/QLocalSocket), окно выходит на передний план и импортирует файл; второе окно не открывается.
- Импорт по командной строке идёт тем же путём, что и из меню: проверка схемы, отчёт об импорте, локальные изменения не теряются.
- Если в файле `kind = changes` — изменения показываются и добавляются в очередь только после подтверждения пользователем. Если `kind = results` — программа закрывает по ним очередь (применённые — убрать, конфликты и отказы — показать).
- Ошибка (файл не найден, не та схема) — понятное окно с причиной, запись в лог; программа при этом открывается (если это не `--help`/`--version`).
- Сценарий с 1С: команда в 1С «Открыть в Ганте» формирует файл во временной папке и запускает `Gantt.exe --import <путь>` (`ЗапуститьПриложение`). Путь к `Gantt.exe` — в настройках расширения.
- Ассоциацию `.json` не регистрировать (слишком общий тип). Если на Этапе 0 предложишь своё расширение файла (например, `.gantt.json`) — обоснуй.

## Модель данных и архитектура

- Модель: дерево узлов с уровнями из справочника. Поля — как в формате: наименование, исполнители, инициатор, план/факт начало и конец, процент, статус, **приоритет, срочность, влияние**, категория, пользовательские поля, версия, признак «изменено локально». Процент проекта, если источник его не прислал, считается по задачам (выполнено/всего, как «3/5» в Excel).
- Источники с общим интерфейсом: `FileSource` (файл обмена) и `HttpSource` (HTTP-сервис). Оба отдают и принимают один и тот же документ.
- Локальный кэш (SQLite): последний полученный документ + метка `cursor` для инкрементов.
- **Слой ожидающих изменений** — поверх данных источника, хранится отдельно, переживает обновления и перезапуск. Это очередь на отправку: по HTTP (`POST`) или экспортом файла `kind = changes`. При обновлении данных, если значение изменилось в источнике, а у нас есть правка, — конфликт, а не молчаливая перезапись.
- Обновление: в HTTP-режиме — инкрементальный запрос раз в N минут; в файловом — слежение за импортированным файлом (QFileSystemWatcher) и переимпорт при его изменении. Без мерцания, с сохранением прокрутки, раскрытых узлов и фильтров. Плюс кнопка «Обновить сейчас».
- **Экспорт** из программы — файл обмена: `full` (снимок текущего состояния с учётом локальных правок) или `changes` (только очередь изменений, для загрузки в 1С без сети).

## Интеграция с 1С (HTTP-сервис)

**Разработка и проверка — только на копии IT-базы.** В рабочую базу ничего не пишется, пока я отдельно не скажу.

### Расширение
Отдельное расширение конфигурации (например, `ГантИнтеграция`); основную конфигурацию не трогаем — в базе уже есть расширения, значит механизм разрешён. Код расширения (BSL, совместимый с платформой 8.3.24; режим совместимости уточнить) пишешь ты, я загружаю его в конфигураторе. Состав:
- общий модуль формирования и разбора файла обмена (один на HTTP и файлы);
- HTTP-сервис;
- обработка или команды: «Выгрузить для Ганта в файл», «Загрузить изменения из файла» (с выдачей файла `results`), «Открыть в Ганте»;
- роль для служебного пользователя;
- регистр сведений — журнал изменений.

### Что узнать о базе (Этап 0)
Я выгружу конфигурацию в файлы (Конфигуратор → Конфигурация → Выгрузить конфигурацию в файлы) и положу в папку проекта. По XML найди и покажи мне таблицей «поле формата → объект/реквизит 1С»:
- какими объектами хранятся проекты, подпроекты, задания и разделы (документ, справочник, иерархия);
- план начала/окончания («Выполнить до» — это план окончания?), факт, процент, статус (тип и значения), исполнитель (реквизит или табличная часть), инициатор, приоритет, срочность, влияние;
- отчёт, который формирует текущую Excel-выгрузку: его запрос — готовая основа для чтения, логика процента (3/5) должна совпадать;
- есть ли у задания история или комментарии, куда уместно писать отметку об изменении.

Поля «Задания» из списка в 1С (со скриншота): Дата, Номер, Тема, Инициатор, Текущий исполнитель, Выполнить до, Приоритет, Категория, Статус задания, Проект, Процесс, Спринт создания/выполнения, Организация, Клиент, Тег, Группа заданий; в карточке также Срочность и Влияние.

Ничего не придумывай про метаданные — только то, что есть в выгрузке. Чего нет — в список вопросов.

### HTTP-контракт
Опиши в `docs/api.md`. Тела запросов и ответов — файл обмена.
- `GET /ping` — версия API, схемы и расширения, имя служебного пользователя.
- `GET /export` — документ `full`; `GET /export?changedSince=<cursor>` — документ `incremental`. Способ отслеживания изменений (план обмена или дата изменения) выбери и обоснуй.
- `POST /import` — документ `changes`; ответ — документ `results` по каждому изменению: `applied` / `conflict` (текущее значение и версия в 1С) / `rejected` (причина: права, поле не разрешено, недопустимый переход статуса и т.п.).

### Правила записи в 1С (и для HTTP, и для файла)
- только через объектную модель (получить объект → изменить → записать), каждый объект в своей транзакции;
- проверка версии данных: если объект изменили в 1С после выгрузки, по которой сделана правка, — конфликт, а не перезапись;
- белый список полей: даты плана, даты факта, статус, процент; остальное только чтение, пока я не решу иначе;
- каждое применённое изменение пишется в журнал (когда, объект, поле, было/стало, кто в программе, с какого ПК, комментарий) и в историю задания, если она есть.

### Пользователь и безопасность
В программе нет авторизации, поэтому к 1С она ходит под **отдельным служебным пользователем** с ролью из расширения: чтение нужных объектов и запись только белого списка полей. ФИО человека, нажавшего «Подтвердить», передаётся в документе и попадает в журнал. Логин и пароль хранить в хранилище учётных данных Windows (keyring), не в файлах настроек. Переключатель «Только чтение» в настройках.

### Поведение программы
- Подключения хранятся как профили: «Файл» (путь или папка) или «HTTP 1С» (адрес публикации, пользователь, пароль, интервал). Экран подключения с кнопкой «Проверить соединение».
- «Подтвердить» (всё или выбранное) → диалог «было → стало», ФИО, комментарий → отправка → результат по каждой строке: применённые уходят из очереди; конфликты — выбор «оставить моё / взять из 1С»; отклонённые — с причиной.
- Нет связи — работа на кэше, в строке состояния «Офлайн, данные на ЧЧ:ММ», очередь копится; её можно выгрузить файлом `changes` и загрузить в 1С вручную.

### Тестовый сервер
Mock-сервер (FastAPI) по тому же контракту на данных из `examples/`: имитирует инкременты, конфликты, отказы и потерю связи. Программа разрабатывается против него (дома доступа к 1С у меня нет), расширение проверяется отдельно на копии базы.

### Запрещено
Писать напрямую в СУБД 1С, менять основную конфигурацию (только расширение), подключать внешние компоненты без согласования, отправлять что-либо в 1С без явного нажатия «Подтвердить».

## Интерфейс

Слева — дерево-таблица (№, Наименование, Исполнители, Статус и др.) со сворачиванием уровней; справа — временная шкала. Прокрутки синхронизированы, шапка и левая часть закреплены.

- Шкала: по умолчанию неделя, переключение день/неделя/месяц/квартал, масштаб колесом с Ctrl, плавный. Выделение текущей недели, линия «сегодня», кнопка «к сегодня».
- Полосы: план — контур/светлая полоса, факт — сплошная тонкая под ней. Цвет по статусу, просрочка заметно выделена. У проекта — сводная полоса с заливкой по проценту.
- **Подсказка при наведении** на план/факт: наименование, исполнитель(и), инициатор, план и факт датами, процент, статус (Выполнено / В работе / Просрочено / В релиз), **приоритет, срочность, влияние** с цветными метками. Набор и порядок полей настраивается; пустые скрываются.
- Приоритет, срочность и влияние — также колонки таблицы (вкл/выкл) и необязательная метка на полосе.
- **Редактирование** (только поля из `editable`): перетаскивание краёв полосы меняет даты (привязка к дню, подсказка новых дат во время перетаскивания), перетаскивание целиком — сдвиг; смена статуса через контекстное меню и двойной клик; ввод факта вручную. Undo/Redo (Ctrl+Z/Ctrl+Y). Изменённое помечено, есть счётчик и панель ожидающих изменений.
- Фильтры (комбинируются): уровень/раздел, исполнитель (мультивыбор), инициатор, статус, приоритет, срочность, влияние, пользовательские поля, период, поиск, «только просроченные», «скрыть выполненные». Сохраняемые наборы фильтров.
- Режимы «Руководитель» (всё) и «Исполнитель» (выбираю себя → свои задачи и их проекты) — переключатель вида, не безопасность.
- Сортировка по любой колонке внутри уровня.
- Меню «Файл»: Импорт…, Экспорт снимка…, Экспорт изменений…, последние файлы. Перетаскивание файла в окно = импорт.
- Отчёт об импорте: сколько уровней/узлов загружено, ошибки схемы, предупреждения (дубли, пустые даты), расхождения с локальными правками.
- **Запоминание настроек:** видимость, порядок и ширина колонок, поля подсказки, наборы фильтров, раскрытые узлы, масштаб, переопределённые цвета справочников, тема, активное подключение.

### Внешний вид и ощущения (важно, не «на потом»)
- Темы: светлая и тёмная, акцентный цвет, переключение на лету с плавным переходом.
- Плавность: анимированное раскрытие/сворачивание, плавная прокрутка и масштаб, анимация появления подсказок.
- «Импакт» от нажатий: лёгкий отклик кнопок (масштаб/ripple/подсветка), анимация перетаскивания полос, короткие всплывающие уведомления.
- ~1000 строк прокручиваются и масштабируются плавно (рисовать только видимое, кэшировать). Эффекты можно ослабить или выключить в настройках.

## Этапы

**Этап 0 — анализ и проектирование (без кода приложения).**
1. Разбери Excel-образец: структура, уровни, статусы, форматы дат, аномалии; сверь числа проектов и задач.
2. Разбери выгрузку конфигурации 1С: таблица соответствия полей, план расширения, способ отслеживания изменений.
3. Формат обмена: JSON Schema, `docs/format.md`, примеры всех видов документов. Проверь универсальность на примере: плоский список задач без иерархии из другой системы должен описываться той же схемой.
4. `docs/api.md`, архитектура программы (модули, источники, кэш, очередь изменений, single instance и командная строка), выбор стека.
5. Макет интерфейса и описание поведения.
6. Список открытых вопросов и рисков.
→ Остановись и жди согласования.

**Этап 1 — формат и просмотр:** схема и валидация, конвертер Excel → файл обмена, импорт файла (из меню, перетаскиванием и из командной строки, single instance), кэш, дерево + шкала, полосы, масштабы, подсказки, фильтры, темы, слежение за файлом. Тесты: схема, конвертер (числа сходятся), командная строка.

**Этап 2 — редактирование:** правки дат/статуса/факта, undo/redo, очередь изменений, конфликты при обновлении, экспорт снимка и изменений, импорт `changes` и `results`.

**Этап 3 — чтение из 1С:** расширение (общий модуль, `GET /ping`, `GET /export`, выгрузка в файл, «Открыть в Ганте»), роль, `HttpSource`, экран подключения, инкременты, офлайн, mock-сервер. Проверка на копии базы: данные совпадают с Excel-выгрузкой того же момента.

**Этап 4 — запись в 1С:** `POST /import` и загрузка изменений из файла с проверкой версий и белым списком, журнал, диалог «Подтвердить», разбор конфликтов и отказов, «Только чтение». Проверка на копии базы, включая одновременную правку в 1С и в программе.

**Этап 5 — полировка:** анимации и эффекты, производительность, настройки и их запоминание, сборка .exe.

**Не делаем пока:** мгновенные уведомления из 1С (push), создание новых задач из программы — записать в `CLAUDE.md` как идеи.

## Критерии готовности
- Файл обмена, полученный конвертером из моего Excel, проходит схему и открывается; числа сходятся с исходником.
- `Gantt.exe путь` и `Gantt.exe --import путь` открывают файл; при уже открытой программе файл уходит в то же окно; пути с пробелами, кириллицей и сетевые работают.
- Один и тот же документ одинаково обрабатывается из файла и по HTTP.
- Файл другой системы по той же схеме (другие уровни, статусы, без иерархии) открывается без изменения кода.
- Приоритет, срочность и влияние видны в подсказке, таблице и фильтрах.
- Правки не теряются при обновлении и перезапуске.
- Подтверждённое изменение видно в 1С и в журнале; параллельная правка в 1С даёт конфликт, а не перезапись; без связи программа работает на кэше, очередь можно выгрузить файлом и загрузить в 1С вручную.
- Интерфейс отзывчивый, анимации плавные на обычном офисном ПК.
- Запускается одним .exe на чистой Windows.
