# Архитектура программы

## Стек

| Что | Выбор | Почему |
|---|---|---|
| Язык | Python 3.14 | PySide6 6.11 и PyInstaller 6.22 с ним работают — проверено сборкой. |
| Интерфейс | PySide6 (Qt 6) | Нативная скорость на ~1000 строк, `QGraphicsView` для шкалы, анимации `QPropertyAnimation`, тёмная и светлая темы. |
| Формат | `json`, `jsonschema` | Стандартные, та же схема проверяет и примеры. |
| Excel | `openpyxl` | Чтение и запись .xlsx, в том числе группировка строк и заливки. |
| HTTP | стандартный `urllib` | Хватает для контракта; запросы идут в фоне (`QThreadPool`), окно не замирает. |
| Пароли | диспетчер учётных данных Windows (`CredWrite`/`CredRead` через `ctypes`) | Без `keyring` и его бэкендов — меньше подвохов при сборке. |
| Кэш и очередь | SQLite (стандартный `sqlite3`) | Один файл, переживает перезапуск. |
| Сборка | PyInstaller | Один .exe или папка — решим по замеру пробной сборки на Этапе 1. |
| Тестовый сервер | стандартный `http.server` | Встроен в программу: «Запустить тестовый сервер» — без Python и 1С. |

Другой стек не предлагаю: Electron или Tauri тяжелее и требуют JavaScript, Tkinter не потянет плавную шкалу.

## Модули

Как сделано (25.09.2026):

```
gantt/
├── app.py                точка входа: аргументы, один экземпляр, русские надписи Qt, повторное открытие
├── single_instance.py    QLocalServer/QLocalSocket: второй запуск передаёт файл первому окну
├── exchange.py           файл обмена: чтение, проверка (схема + смысл), русские сообщения, incremental
├── model.py              Dataset: дерево узлов, справочники, правки поверх снимка, процент, просрочка, editable
├── store.py              SQLite: правки по наборам данных (со значением источника — для конфликтов)
├── settings.py           настройки вида (INI в %LOCALAPPDATA%\Гант)
├── http_source.py        HTTP-контракт: профили, запросы, пароль в диспетчере учётных данных Windows
├── mock_server.py        тестовый сервер по контракту (http.server)
├── formats/              адаптеры: json_format, report_1c, table (мастер), gantt_table (Excel/CSV), msproject
└── ui/
    ├── main_window.py    окно: файлы, правки с отменой, режимы, раскрытие, сохранение
    ├── tree_model.py     модель дерева для обеих половин, фильтры и сортировка (прокси)
    ├── table.py          левая половина: колонки, делегаты, «+/−»
    ├── timeline.py       правая половина: шкала, полосы, зависимости, перетаскивание, масштаб
    ├── render.py         PNG/PDF — той же отрисовкой полос, что на экране
    ├── wizard.py         мастер сопоставления колонок
    ├── export.py         «Сохранить как» с выбором формата, лист изменений
    ├── incoming.py       пришедшие changes и results
    ├── server.py         подключения, «Подтвердить», офлайн
    ├── filters.py, panels.py, dialogs.py, widgets.py, smooth.py, theme.py, tasks.py
```

Правило зависимостей: `ui` → `editing` / `sync` → `model` → `exchange`. `formats` и `sources` знают только `exchange`. Ядро (`exchange`, `model`) не знает ни про Excel, ни про 1С.

## Поток данных

```
файл / сервер ──► адаптер ──► документ ──► проверка ──► хранилище (снимок набора)
                                                            │
                          очередь правок ──► модель = снимок ⊕ правки ──► дерево + шкала
                                ▲                                            │
                                └───────────── правка пользователя ◄─────────┘

очередь ──«Подтвердить»──► changes ──► сервер ──► results ──► очередь закрывается
очередь ──────────────────► «Сохранить как» / «Лист изменений» (без сервера)
```

## Наборы данных

- **Набор данных** = `meta.source` + `meta.sourceName`. У каждого набора свой снимок, свой `cursor` и своя очередь правок.
- Если открыть файл другой системы, данные 1С и их очередь не смешаются.
- Последние наборы — в меню «Файл → Последние». Активный набор открывается при запуске.

## Хранилище

- **Путь** — `%LOCALAPPDATA%\Гант\data.sqlite`: всегда локально, даже если программа лежит на сетевом диске.
- **Таблицы:**
  - `datasets` — наборы данных;
  - `snapshots` — последний документ источника, `cursor`, время загрузки;
  - `pending_changes` — очередь: `changeId`, узел, поле, было, стало, `baseVersion`, время, состояние (ждёт / отправлено / конфликт / отказ), кто подтвердил;
  - `import_log` — журнал загрузок.
- **Настройки вида** (колонки, фильтры, раскрытые узлы, масштаб, тема, цвета справочников) — `QSettings`, отдельно по наборам.

## Слой правок и конфликты

- **Видимое значение поля** = правка из очереди, если есть, иначе значение источника. Снимок источника не меняется, поэтому правки переживают обновления и перезапуск.
- **Каждая правка** — команда в `QUndoStack`: Ctrl+Z / Ctrl+Y. Повторная правка того же поля обновляет запись в очереди, `oldValue` остаётся исходным.
- **При обновлении из источника**, для каждой правки:
  - новое значение источника равно `oldValue` — ничего не изменилось, правка живёт;
  - равно правке — источник уже принял это значение, правка снимается;
  - другое — **конфликт**: пользователь выбирает «оставить моё» (новый `oldValue`) или «взять из источника» (правка снимается).
- **Удалённый в источнике узел с правками** — конфликт с выбором «убрать правки».

## Обновление

- **Файл:** `QFileSystemWatcher` + запасной опрос размера и времени изменения — на сетевых папках уведомления ненадёжны.
  - После изменения — пауза 1 с, чтобы писатель закончил.
  - При ошибке разбора — три повтора: файл мог быть записан не до конца.
- **Сервер:** `GET /export?changedSince=` раз в N минут и по кнопке «Обновить сейчас». При ошибке — «Офлайн, данные на ЧЧ:ММ», работа на кэше, повторы с нарастающей паузой.
- **Без мерцания:** изменения применяются к модели по месту. Прокрутка, раскрытые узлы, выделение и фильтры держатся по `id` узлов.

## Командная строка и один экземпляр

```
Gantt.exe "C:\путь\файл.json"
Gantt.exe --import "\\сервер\папка\отчёт.xlsx"
Gantt.exe --help | --version
```

- **Путь.** Позиционный путь и `--import` — одно и то же. Любой поддерживаемый формат. Пути с пробелами, кириллицей и UNC — через `pathlib`, без опоры на текущую папку.
- **Один экземпляр:**
  - первый запуск слушает канал `QLocalServer` с именем, включающим пользователя (на терминальном сервере у каждого своё окно);
  - второй запуск отправляет `{"cmd": "import", "path": …}`, разрешает первому выйти на передний план (`AllowSetForegroundWindow`) и завершается;
  - первое окно поднимается и открывает файл тем же путём, что и меню.
- **`--help` и `--version`** у оконного .exe: вывод в консоль, из которой запустили (`AttachConsole`), иначе окно с текстом.
- **Ошибки** (нет файла, не тот формат, не прошла проверка) — понятное окно и запись в лог `%LOCALAPPDATA%\Гант\logs`. Программа при этом открывается.

## Интерфейс изнутри

- **Слева** — `QTreeView` с моделью поверх отфильтрованного и отсортированного дерева. Колонки, порядок, ширина и сортировка внутри уровня даются Qt.
- **Справа** — второй `QTreeView` на той же модели (видна только колонка шкалы), полосы рисует делегат. Так строки, раскрытие и прокрутка двух половин совпадают без отдельной раскладки. В планах был `QGraphicsView`:
  - шкала (день, неделя, месяц, квартал), линия «сегодня», текущая неделя;
  - полосы плана и факта, сводные полосы, вехи, зависимости;
  - рисуется только видимое.
- **`RowLayout`** — единая раскладка строк: какие строки видны и на какой высоте. Её читают обе половины, поэтому прокрутка и анимация раскрытия у них совпадают кадр в кадр. Это самое тонкое место интерфейса, его делаем первым.
- **Масштаб** колесом с Ctrl — плавный, с опорой на точку под курсором.
- **Темы:**
  - цвета из макета заданы токенами и применяются к `QPalette`, стилям и сцене;
  - при переключении темы — плавный переход;
  - анимации можно ослабить или выключить.
- **Цели по скорости:**
  - 1000+ строк прокручиваются и масштабируются плавно на офисном ПК;
  - файл на 1000 узлов открывается меньше чем за секунду.

## Сборка

- Пробная сборка .exe — уже на Этапе 1: так проблемы упаковки всплывут рано.
  - Известные подвохи: бэкенды `keyring`, данные `jsonschema`, плагины Qt.
- Шрифты макета (IBM Plex Sans/Mono, Unbounded — лицензия OFL) встраиваются в .exe.
- Один .exe при каждом запуске распаковывается во временную папку — это несколько секунд, и антивирусы иногда ругаются. Если замер покажет, что это мешает, соберём папку с .exe на сетевом диске.

## Тесты

- **Проверка формата:** все примеры проходят; заведомо плохие файлы дают нужные русские сообщения.
- **Excel-адаптер:**
  - на обезличенном примере — всегда;
  - на примере пользователя из `local/` — если он есть: открывается без ошибок, числа сходятся с `local/expected.json`.
- **Туда и обратно:** сохранить в каждый формат и открыть — данные те же (с учётом того, что формат теряет).
- **Командная строка:** пути с пробелами, кириллицей, UNC; передача файла во второй экземпляр.
- **Слой правок:** конфликты, снятие принятых правок, переживание перезапуска.
